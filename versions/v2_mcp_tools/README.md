# Version 2 — MCP Tool Integration

The first MCP build. Archived, unchanged in architecture, still runnable.

```text
User
 ↓
Pure Python Agent
 ↓
MCP Client
 ↓
Tool Discovery      (client.list_tools())
 ↓
MCP Server          (server.py, a separate stdio subprocess)
 ↓
Tool Execution
```

![V2 architecture](../../docs/architecture/v2-mcp-tools.png)

## What changed from version 1

| | Version 1 | Version 2 |
|---|---|---|
| Tool wiring | `TOOLS_BY_NAME` dict | discovered via `client.list_tools()` |
| Tool schemas | hand-written JSON | generated by FastMCP from type hints and docstrings |
| Execution | direct Python call | `await client.call_tool()` over stdio |
| Tool process | same process as the agent | separate subprocess |
| Backends | Ollama + Groq | Ollama only |
| Calculator | raw `eval()` | AST walker, arithmetic only |

The payoff: adding a tool means writing one decorated function in `server.py`.
No schema to write, no registry to update, no frontend change. The same server
works with any other MCP client, Claude Desktop included.

The cost: a fresh `python server.py` subprocess spawns on every message, and
the tool schemas are re-sent to the model on every turn.

## Files

| File | Role |
|---|---|
| `app.py` | agent loop **and** MCP client, in one module |
| `server.py` | FastMCP server exposing the four tools |
| `client.py` | a minimal "just list the tools" client, useful for poking at the server |
| `streamlit_app.py` | Streamlit UI that captures the agent's stdout trace |

Note that `app.py` mixes agent reasoning with MCP client plumbing. Pulling
those apart is exactly what `src/agenticgpt/` does.

## Running it

```bash
cd versions/v2_mcp_tools
pip install -r requirements.txt
ollama pull qwen3:8b
ollama serve
```

Set `WEATHER_API_KEY` and `TAVILY_API_KEY` in the repository-root `.env`, then:

```bash
python app.py
```

```bash
streamlit run streamlit_app.py
```

The MCP server starts itself — the client spawns it over stdio. There is no
second terminal and no separate `python server.py`.

To inspect the server on its own:

```bash
python client.py
```

## Changes made during the repository restructure

Architecture untouched. Three path/secret fixes only:

- hardcoded WeatherAPI key → `os.environ.get("WEATHER_API_KEY")`
- `streamlit_app.py` imported `from mcp_server.app import run_agent`; the package
  folder is gone, so it now imports `from app import run_agent`
- `client.py` resolved `server.py` relative to the working directory; it now
  resolves relative to `__file__`
